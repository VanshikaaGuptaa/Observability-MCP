# 19. What counts as a PASS?

Don't judge the MCP simply by whether Antigravity produces a nice-looking answer.

The important acceptance criteria are:

### MCP behavior

```text
Correct tool
      ↓
Correct query
      ↓
Correct data
      ↓
Correct interpretation
      ↓
Correct uncertainty handling
```

### Agent behavior

```text
User asks investigation
        ↓
Antigravity
        ↓
MCP tools/resources
        ↓
Evidence
        ↓
Investigation
```

NOT:

```text
User asks investigation
        ↓
Antigravity
        ↓
Read source code
        ↓
Run random commands
        ↓
Modify files
        ↓
Guess diagnosis
```

# 20. The most important failures to watch for

Before moving to **MCPGuard**, I would specifically look for these:

### ❌ Failure 1 — Missing metric becomes zero

```text
Prometheus: no result

MCP:
p95 = 0

```

Should be:

```text
p95 = unavailable
```

---

### ❌ Failure 2 — Historical incident reported as active

```text
Payment failed 8 minutes ago
Current payment is healthy
```

Agent says:

```text
ACTIVE PAYMENT INCIDENT
```

Wrong.

---

### ❌ Failure 3 — Dependency failure automatically means outage

```text
Redis errors
+
HTTP 200
```

Agent says:

```text
OrderFlow is down
```

Wrong.

---

### ❌ Failure 4 — Root cause asserted without evidence

Bad:

```text
Root cause: Redis caused the outage.
```

when all you know is:

```text
Redis errors occurred.
```

Better:

```text
Hypothesis: Redis degradation affected the product lookup cache.

Evidence: Redis errors were observed while the endpoint remained
available through fallback.
```

---

### ❌ Failure 5 — Agent bypasses MCP

If you ask:

> "Investigate OrderFlow."

and Antigravity does:

```text
Get-Content main.go
grep...
```

instead of MCP calls, that's an **agent integration failure**.

---

### ❌ Failure 6 — MCP query injection

Input:

```text
endpoint = "/api/products] ..."
```

should not become arbitrary PromQL.

Your MCP should validate the parameter **before constructing the query**.

---

### ❌ Failure 7 — MCP starts modifying things

Observability MCP v1 should be:

```text
READ ONLY
```

It should investigate, not fix.

That separation becomes extremely valuable when you build:

```text
                 ┌──────────────────┐
Antigravity ────►│     MCPGuard     │
                 │                  │
                 │ authorization    │
                 │ identity         │
                 │ approval         │
                 │ audit            │
                 └────────┬─────────┘
                          │
                          ▼
                 Observability MCP
                          │
              ┌───────────┼───────────┐
              ▼           ▼           ▼
         Prometheus     Loki     Deployments
```

**So don't move to MCPGuard just because the tools work once.** Run these tests, especially the **recovery, timeline, unknown-data, validation, and workspace-isolation tests**. Those are what will make the Observability MCP a solid foundation rather than just an MCP wrapper around Prometheus and Loki.
